# План реализации облачного Lockbox

Основа: [Lockbox Protocol](lockbox-protocol.md). Уточнение продукта: локальный
однопользовательский режим либо облачный многопользовательский режим со Storj.

## Идентичность и шифрование (proposal §§7, 9, 25)

- [x] Подключить Ed25519-dalek 2.2.0 и HPKE 0.13.0 с X25519 и очисткой секретных ключей.
- [ ] Провести независимое ревью выбранных библиотек и их использования.
- [x] Создавать корневую идентичность пользователя и отдельные ключи устройства;
  отображаемое имя пользователя не является криптографической идентичностью.
- [x] Создавать случайные space ID, K_epoch и epoch_context; выводить отдельные
  ключи изменений и checkpoint через HKDF по протоколу.
- [x] Реализовать начальный зашифрованный профиль v3: имена, credentials и ключи;
  корневой ключ дополнительно защищён отдельным паролем восстановления.
- [x] Блокировать одновременное открытие профиля через lock-файл.
- [ ] Дополнить профиль состоянием протокола: anchors, counters, outbox,
  installation binding и правилами восстановления без клонирования signer.
- [ ] Создавать genesis, сертификат устройства и начальное состояние владельца.
- [x] Проверить сохранение, повторное открытие, неправильные пароли,
  повреждения, отсутствие credentials в открытых файлах и сохранность ключей.
- [ ] Проверить аварийное завершение и восстановление профиля на другом устройстве.

## Последующие этапы

- [ ] Модель протокола и conformance fixtures, проверка подписей и полномочий.
- [ ] Membership, приглашения, grants, отзыв устройств и смена эпох.

- [ ] UI участников, приглашений, конфликтов и восстановления.
- [ ] Независимое ревью безопасности перед выпуском облачного режима.

Облачный flow создаёт локальный профиль и начальные ключи. Его формат v3
пока содержит bootstrap-схему версии 1, а не полное состояние протокола §25.
Сертификаты, genesis, signing counters и операции облачного обмена ещё не
создаются. Без них профиль не является участником общего пространства.
Локальный .lbx с ключами устройства никогда не загружается как общий cloud-файл.
Копирование профиля на другие устройства не является процедурой их подключения.

Подготовка Storj сверена с [официальной документацией](https://storj.dev/dcs/api/s3/credentials).
Инструкция включена в приложение и доступна без сети. Проверка формы выполняется
локально и не подтверждает доступ к bucket. Профиль сохраняется после выбора
файла; отмена диалога не запускает генерацию ключей.
