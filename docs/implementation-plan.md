# План реализации облачного Lockbox

Основа: [Lockbox Protocol](lockbox-protocol.md). Уточнение продукта: локальный
однопользовательский режим либо облачный многопользовательский режим со Storj.

## Первый этап: создание хранилища

- [x] Прочитать proposal и сопоставить с текущим локальным форматом v2.
- [x] До выбора файла показать выбор типа хранилища.
- [x] Сохранить локальный flow: путь → мастер-пароль → зашифрованный файл.

  Base URL, Access Key, Secret Key.

- [x] Исключить создание локального v2-файла под видом облачного хранилища.
- [x] Добавить [отдельную инструкцию подготовки Storj](storj-setup.txt) и переход к ней из формы.
- [x] Разделить Base URL gateway, Bucket и отображаемое имя хранилища.
- [ ] Определить prefix по случайному space ID и проверить подключение без записи секретов в логи.
- [x] Добавить проверку полей и переход к мастер-паролю для локального профиля.

## Идентичность и шифрование (proposal §§7, 9, 25)

- [ ] Выбрать и проверить Rust-библиотеки Ed25519 и HPKE.
- [ ] Создавать корневую идентичность пользователя и отдельные ключи устройства;
  отображаемое имя пользователя не является криптографической идентичностью.
- [ ] Создавать случайные space ID, K_epoch и epoch_context; выводить отдельные
  ключи изменений и checkpoint через HKDF по протоколу.
- [ ] Реализовать зашифрованный локальный профиль v3: имена, credentials,
  ключи и состояние пространства; не помещать их в открытый config.json.
- [ ] Создавать genesis, сертификат устройства и начальное состояние владельца.
- [ ] Проверить сохранение, повторное открытие, неправильный пароль,
  повреждения, отмену создания и отсутствие секретов в открытых файлах.

## Последующие этапы

- [ ] Модель протокола и conformance fixtures, проверка подписей и полномочий.
- [ ] Membership, приглашения, grants, отзыв устройств и смена эпох.
- [ ] Изменения, причинный граф, конфликты, checkpoints и durable outbox.
- [ ] Тестовый adversarial transport, затем S3-совместимый адаптер Storj.
- [ ] Синхронизация двух клиентов, обработка сбоев и повторов.
- [ ] UI участников, приглашений, конфликтов и восстановления.
- [ ] Независимое ревью безопасности перед выпуском облачного режима.

Облачная форма первого этапа является подготовкой интерфейса. Она не создаёт
облачное хранилище и не сохраняет введённые данные после закрытия формы.
Локальный .lbx с ключами устройства никогда не загружается как общий cloud-файл.

Подготовка Storj сверена с [официальной документацией](https://storj.dev/dcs/api/s3/credentials).
Инструкция включена в приложение и доступна без сети. Проверка формы выполняется
локально и не подтверждает доступ к bucket. Кнопка создания облачного профиля
остаётся недоступна до реализации ключей и формата v3.
