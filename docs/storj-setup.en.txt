1. Create a project in the Storj console and a separate bucket for Lockbox. Use 3–63 characters for a new bucket: lowercase Latin letters, digits, and hyphens; start and end with a letter or digit.

2. Under Access Keys, choose New Access Key and the S3 Credentials type. Give the access a name that distinguishes it from other applications.

3. Choose Advanced and restrict access to the selected bucket. Lockbox needs Read, Write, and List for object exchange. Set an expiration that suits your needs.

4. Complete the Storj encryption passphrase step. This passphrase belongs to Storj; the master password for your local Lockbox profile is set separately.

5. Save the Access Key, Secret Key, and Endpoint. In Lockbox, Base URL is the gateway Endpoint, without a bucket name or path. Enter the bucket separately in the Bucket field.

6. Enter your username and the vault's name in Lockbox. Choose a unique space name within the bucket: S3 objects use spaces/<space name>/objects/. The name can differ from the bucket name and does not grant access rights. It appears in the header and unlock page, and signed invitations carry it to joining devices.

After validating the fields, choose one master password and save the 12 recovery words; the words and your vault file or backup can restore access if you forget the password. The app saves the .lbx profile in your private ~/.lockbox directory. Credentials and keys stay inside the encrypted profile. The space name is also cached in local settings for the unlock page and is visible in S3 keys and signed invitations. Once opened, new profiles exchange encrypted, signed events through Storj; network errors leave changes saved on your device. The form checks syntax; actual permissions are checked during sync. Do not upload the local profile to a shared bucket or copy it to another device for collaboration. To join an existing space, select Join a space on the welcome screen and use independent credentials for the owner’s storage. No vault name is required. Then exchange files through Sharing and participants; The wizard shows the current step’s action and detects file types automatically. Copy the message with your username, User ID and Device ID and send it to the administrator through a second trusted channel, separately from the request file. The exchange format is experimental and unversioned. Previous versions are unsupported.
