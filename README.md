# lockbox

Менеджер паролей с TOTP-кодами. Локальный режим хранит всё в одном
зашифрованном файле `.lbx`. Облачный режим сохраняет изменения на устройстве
и обменивается зашифрованными подписанными событиями через Storj.

Интерфейс — Dioxus 0.7: компоненты на Rust, реактивное состояние через
`use_signal` и `Context`, стили и SVG-иконки встроены в бинарник. На десктопе
используется системный WebView с локальным транспортом Dioxus; внешние
ресурсы не загружаются. Пока целевая платформа — macOS; переход на
Dioxus сам по себе не добавляет сборку для iOS.

Оформление вдохновлено [Apple Liquid Glass](https://developer.apple.com/design/human-interface-guidelines/materials):
матовые полупрозрачные панели навигации, отдельные поверхности для паролей,
системный шрифт и встроенные контурные иконки. Эффект реализован CSS в WebView;
на macOS используется прозрачная область заголовка с системными кнопками окна.
Светлая и тёмная темы автоматически следуют системной теме при запуске и
переключаются в открытом приложении без перезапуска. Цвета интерфейса,
элементов форм и фона окна обновляются вместе; тема перепроверяется при
возврате в приложение и после возобновления работы. Уменьшение движения,
прозрачности и повышенный контраст следуют настройкам, которые сообщает WebView.
Кнопки действий показывают иконки; названия доступны в подсказках при
наведении и программах экранного доступа.

На экране разблокировки — компактное поле мастер-пароля и значок ключей.
Enter или стрелка в поле открывают хранилище; отпечаток на значке запускает
Touch ID, если он включён. Кнопки открытия, создания и забывания пути находятся
внизу окна.

Модели разблокировки, сессии, списка записей и черновика находятся в
`src/app/{auth,session,workspace,editor}.rs` и не зависят от Dioxus.
Модель папок и проверка иерархии находятся в `src/core/folder.rs`, навигация и
сохранение изменений — в `src/app/directories.rs`, поиск по дереву — в
`src/app/tree.rs`. Представление дерева, формы папок и выбор расположения
записи — отдельные компоненты в `src/ui/components/`.
Настройки, биометрия и системные сервисы вынесены отдельно. `context.rs`
задаёт независимые контексты, `runtime.rs` связывает их с жизненным циклом
окна, а компоненты лежат в `src/ui/components/`. Часы и строка статуса имеют свои
сигналы: их обновления не перерисовывают подписчиков состояния хранилища.

## Облачный профиль: идентичность и ключи

В создании хранилища выберите многопользовательский режим, заполните настройки
Storj, имя пользователя и имя хранилища. После проверки полей задайте мастер-пароль
и отдельный пароль восстановления (каждый не менее 12 символов), затем выберите
файл локального профиля `.lbx`. Отмена выбора файла не создаёт ключи.

Приложение создаёт независимые Ed25519-ключи пользователя и устройства,
HPKE X25519-ключ устройства, случайные ID пространства, namespace, ключ эпохи
и её контекст. Ключи изменений и checkpoint выводятся через HKDF по proposal.
Полные публичные отпечатки доступны на стартовом экране открытого профиля.

Имена, credentials и ключи устройства хранятся внутри зашифрованного файла v3
(Argon2id, HKDF-SHA256, XChaCha20-Poly1305). Корневой ключ дополнительно
зашифрован отдельным паролем восстановления с независимой солью. Мастер-пароль
и Touch ID открывают профиль, но не снимают эту дополнительную защиту.
При открытом профиле файл `.lbx.lock` блокирует второе открытие; оставшийся
после закрытия lock-файл не означает, что профиль заблокирован.

Новые профили содержат сертификат устройства, подписанный genesis и durable
outbox. Сохранение записи или папки сначала фиксирует локальное событие;
фоновый обмен со Storj не требует доступности сети для локальной работы.
Проверяются подписи, роли, цепочка участников, причинные зависимости и счётчики
устройств. Параллельные версии сохраняются до явного разрешения конфликта.
Изменение состава участников меняет ключ эпохи; поздние изменения остаются
доступны для проверки и переноса.

Движок использует экспериментальный профиль `LBX-SYNC-0`, отдельный от полного
proposal v1. API подключения независимых профилей и изменения состава участников
реализован; экраны приглашений и участников ещё отсутствуют. Старые bootstrap
профили версии 1 активируются отдельным паролем восстановления с сохранением
существующих записей и идентичности устройства. Профиль
не загружается в общий bucket и не копируется для подключения другого устройства.
Существующие локальные файлы v1/v2 остаются совместимыми.

Описание границ, API и проверки: [движок синхронизации](docs/sync-engine.md).
Рабочий пример двух клиентов без сети: `cargo run --example shared_space`.
Проверки используют adversarial transport и локальный S3 HTTP fixture;
live-bucket Storj и независимое ревью безопасности пока не выполнены.

## Структура кода

```text
src/
  core/            записи, папки, TOTP и генерация паролей
  app/             сценарии, сессия, черновики и навигация
  infra/           файлы хранилища, настройки и системные сервисы
  ui/              Dioxus runtime, контексты и каталог иконок
    components/    компоненты интерфейса и стилизация
  bin/             инструменты сборки ресурсов
  lib.rs           границы модулей и совместимые публичные импорты
  main.rs          запуск desktop-приложения
```

`core` не зависит от интерфейса и системных адаптеров. `app`
использует модели и сервисы `infra`, но не зависит от Dioxus.
`ui` связывает сценарии с реактивными контекстами и компонентами.
Системные зависимости остаются в `infra`; существующий контракт
`Biometrics` позволяет подменять биометрию в тестах. Старые публичные пути
(`lockbox::vault`, `lockbox::app::App` и другие) сохранены в `lib.rs`;
внутренний код использует пути соответствующих слоёв.

## Запуск

```sh
cd lockbox
cargo run --release
```

При первом запуске — «Создать хранилище…» и место для файла вне репо
(`*.lbx` в `.gitignore`, но лучше не держать его рядом с кодом). Последний
открытый файл запоминается в `~/Library/Application Support/lockbox/config.json`;
кнопка «Забыть путь» убирает его оттуда.

## Как защищены данные

- Мастер-пароль → Argon2id (256 МиБ, 3 прохода) → HKDF → ключ
  XChaCha20-Poly1305. Шифруется всё содержимое целиком, заголовок файла
  тоже защищён от подмены.
- Сохранение атомарное: временный файл → fsync → переименование;
  предыдущая версия остаётся рядом как `.lbx.bak`.
- Ключ и записи в Rust стираются из памяти при блокировке и закрытии окна.
  При блокировке компоненты с записями и формами удаляются из интерфейса.
  Введённые и показанные секреты также проходят через DOM, JavaScript и
  виртуальный DOM Dioxus: гарантировать стирание этих копий из памяти WebView
  нельзя.
- Скопированный пароль или код помечается для менеджеров буфера как скрытый
  и стирается из буфера через 20 с — если там всё ещё он.
- Автоблокировка: после выбранного в настройках хранилища времени без действий
  (по умолчанию 5 минут), после сна мака дольше этого времени и сразу при
  блокировке экрана. Несохранённая правка записи при этом сбрасывается; за 30 с
  окно предупреждает.

## Папки

Боковая панель показывает компактное дерево: у записей видны только названия,
у папок — стрелки раскрытия. Кнопка с папкой и плюсом создаёт папку; внутри
папки можно создавать подпапки, переименовывать её и менять расположение.
Запись помещается в выбранную папку; перенести её можно в поле «Папка» при
редактировании. Поиск раскрывает путь к найденным записям и ищет также по
названиям папок, логинам и адресам сайтов.

Папки, их вложенность и расположение записей шифруются вместе с хранилищем.
Старые файлы v1 открываются автоматически: прежние записи находятся в корне.
При сохранении используется формат v2, чтобы старые версии приложения не
могли незаметно потерять структуру папок при перезаписи файла.
Удаление папки и её подпапок перемещает все записи на уровень выше. Если
сохранение не удалось, иерархия и расположение записей остаются прежними.

## Иконки

Логотипы сервисов — из [Simple Icons](https://simpleicons.org) (версия в
`assets/SIMPLE_ICONS_VERSION`), вшиты в приложение: lockbox их не скачивает.
Иконка подбирается по домену URL записи (`mail.google.com` → Gmail,
остальное под `google.com` → Google, `gitlab.com` → GitLab); если не нашлась —
первая буква названия на цветном квадрате. В правке записи можно выбрать любую
иконку из набора.

Домены, которые не совпадают с названием иконки, лежат в
`assets/icon_domains.txt`. После правки или для новой версии набора:

```sh
curl -fsSO https://registry.npmjs.org/simple-icons/-/simple-icons-<версия>.tgz
tar -xzf simple-icons-<версия>.tgz
cargo run --bin build-icons -- package
```

Набор распространяется под CC0, но сами логотипы — товарные знаки их
владельцев: см. `assets/DISCLAIMER-simple-icons.md`.

## Touch ID

Включается переключателем «Touch ID» в настройках открытого хранилища
(кнопка с ползунками в верхней панели). Мастер-пароль всё равно
нужен: каждые 7 дней, после смены набора отпечатков в системе и если Touch ID
не сработал.

**Ограничение.** Ключ хранилища лежит в связке ключей (элемент `lockbox`), а
отпечаток проверяет сам lockbox. macOS не привязывает этот элемент к пальцу:
программа, которой вы разрешите доступ к элементу `lockbox` («Разрешать
всегда»), получит ключ без Touch ID. Настоящая привязка требует подписи с
аккаунтом Apple Developer — без неё macOS отвечает `errSecMissingEntitlement`.
После каждой пересборки macOS один раз спросит, можно ли lockbox читать этот
элемент: подпись меняется.

в предложении возможности пока не реализованы.
