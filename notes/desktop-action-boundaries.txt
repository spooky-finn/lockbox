Desktop action boundaries

Runtime owns lifecycle: context setup, clock, worker polling, lock, clipboard.
Profile adapter owns tab coordination, profile selection, creation entry points.
Settings adapter owns preference commands, active security updates, error routing.
Record dialogs own import/attachment pickers; reuse existing feature module.
Sharing workflow owns pairing completion; runtime persists recent-profile metadata.

Adapters may depend on Dioxus/session handles. Settings persistence, vault,
protocol keep existing framework-independent contracts. No new service traits:
existing concrete collaborators sufficient; avoid interfaces without substitution need.
Private callers import owning modules directly; no forwarding facade in runtime.
Public compatibility exports unchanged.

Security invariants: lock still cancels workers and clears guarded clipboard.
Delayed attachment callbacks require unlocked vault plus matching path and
record/draft identity before plaintext I/O. Pairing completion still precedes
recent-profile persistence; failed cloud restore resumes reserved target.
