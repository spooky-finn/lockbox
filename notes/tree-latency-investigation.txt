Tree/filter latency investigation — 2026-11-17

Scope
- Current working tree; existing uncommitted UI edits retained.
- Dioxus 0.7.10, macOS Apple Silicon, unoptimized test build.
- Investigation + opt-in timing probe. No production behavior changes.

Measured
- New probe: src/records/views/tests/tree_performance.rs.
- Fictional local vault. 100 / 1,000 / 10,000 records; one folder per ten records.
- All folders initially open; ten records per folder; 20 samples per operation.
- Timed command separately from render_immediate_to_vec(). Includes full fixture
  component work, Dioxus scheduling/diff and mutation collection.
- Excludes native event delivery, IPC serialization, browser DOM/layout/paint,
  network sync, journal replay, attachments. No native latency claim.
- Median / p95 Rust render milliseconds:
                         100             1,000             10,000
  Select record          1.57 / 1.63     11.55 / 11.92    115.30 / 116.37
  Toggle folder          1.48 / 1.51     11.55 / 11.78    118.62 / 119.79
  Filter same rows       1.75 / 1.80     13.84 / 15.24    159.44 / 168.15
  Remove/restore rows    1.64 / 1.88     13.10 / 14.75    132.06 / 155.90
  Session notification   0.73 / 0.77      4.45 /  4.68     42.29 /  42.74
- Remove/restore alternates two different workloads; aggregate percentiles only.
- Selection/toggle assert zero extra hierarchy projections. Commands under 1 ms
  in this run. Large delay remains after existing metadata/sorting caches.
- 10,000-record selection: seven mutations at median sample, 115 ms Rust work.
- Identical-result filtering: one mutation at median sample, 159 ms Rust work.
- Restore can produce ~135,000 mutations before WebView applies anything.
- Session notification baseline still grows with tree size; exact internal
  attribution needs profiler. Do not assign whole baseline to one component.

High-priority findings
1. Whole visible tree rebuilt on selection/expansion.
   src/records/views/sidebar.rs: tree_key includes selection + collapsed folders;
   tree_view depends on key, invokes nodes_ui for complete hierarchy.
   src/records/views/tree.rs: ordinary recursive function, no row component
   boundary. Recreates row strings, handlers and VNodes for every visible node.
   Stable keys preserve DOM identity; do not skip this Rust construction work.
   Confirmed scaling above. Large root lists remain completely mounted.
   Next: virtualize visible rows, or isolate row updates with targeted state.
   Simply giving every row same Session read still wakes every subscriber.

2. Search does full scan/sort and reveals all matching branches per input.
   sidebar.rs: input immediately writes Session; query changes PresentationKey,
   nodes and tree_view. tree.rs: metadata key clones record display metadata;
   project rebuilds maps + sibling sorting; matching lowercases fields again.
   views/tree.rs: searching forces matching branches open. Common query can
   turn compact tree into thousands of mounted rows in one synchronous update.
   Same-result search still explicitly rebuilds rendered tree on query change.
   Next: cache sorted topology by records revision; filter without re-sorting;
   retain only display metadata/match decisions; coalesce expensive queries;
   virtualize matches. Keep input updates immediate and lock cleanup intact.

3. Shared-vault journal verification runs during ordinary rendering.
   src/desktop/sync_review.rs: SyncReview reads Session and invokes
   vault.sync_replay_state() in rsx. src/vault/shared.rs passes directly to
   Machine::replay_state; machine/replay.rs verifies complete control/history
   and decrypts changes. No memo around replay in this component.
   Thus ordinary navigation/search can repeat cryptographic history work even
   when journal unchanged. Potential severe delay with modest visible trees.
   Code-confirmed; shared-history latency NOT measured by local-vault probe.
   Next: publish cached review summary after verified journal changes. Cache key
   must cover complete replay inputs, faults and pending exchange state, beyond
   records revision alone. Keep revealed secrets scoped and cleared on lock.

Additional costs
- Session = Signal<Screen>. Sidebar, UnlockedView, VaultContent, EntryView,
  DirectoryView, Toolbar, SyncReview and several memos read same signal.
  Any write wakes broad dependency set. Existing memos reduce some derived
  work; do not remove all subscribers. Baseline measurement confirms residual
  size-dependent cost without hierarchy projection.
- DirectoryView rebuilds folder index and counts subtree records/folders on
  every Session notification. Contains walks lineage with visited-set allocation
  per candidate. Cache display summary by folder ID + records revision.
- Selecting entry scans entries and rebuilds folder hierarchy to reveal lineage.
  Lower cost in probe; index IDs/parents after larger bottlenecks addressed.
- assets/tree-navigation.js queries all visible buttons, scans aria-current and
  finds current index before checking navigation key. Arrow repetition crosses
  JS/Rust bridge and triggers selection renders. Filter handled keys before DOM
  scan; profile native repeat/IPC; preserve unsaved-draft guard and focus rules.
- Explicit save + sync completion still can block UI with crypto/durable writes.
  scheduler.advance applies downloaded batches and replays on caller thread.
  Tree clicks themselves do not persist unless user resolves pending draft Save.
  Do not mistake background-triggered stalls for tree projection alone.
- CSS transitions ~140 ms can delay visual settling; large DOM adds layout/paint.
  Neither measured here; Rust delay already reproduced without browser.

Dioxus evidence
- Official 0.7 signals docs: read() during render subscribes component.
  https://dioxuslabs.com/learn/0.7/essentials/basics/signals/
- Official memo docs: dependencies rerun computation; equality gates consumers.
  https://dioxuslabs.com/learn/0.7/essentials/basics/effects/
- Installed 0.7.10 source: signals/src/memo.rs recompute calls callback before
  PartialEq. core/src/nodes.rs VNode equality compares Rc pointers. Fresh VNode
  memo result gives no structural bailout for rebuilt nodes_ui output.
- No evidence requiring framework replacement or dependency upgrade.
